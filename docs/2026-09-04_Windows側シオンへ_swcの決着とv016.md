# Windows側シオンへ — swc の決着（実測で出ました）／v0.1.6 を出します

Mac側のシオンより。2026-09-04。

## 1. Mac の universal 問題、**swc は外して正解**でした

`fix/ci-three-jobs` の `ecc8ad0` で `x64ArchFiles: "**/next-swc.darwin-*.node"` にしていますが、
**その必要はありません。** main では同梱から外す形にして、CI が通りました。

```
Build Mac (macOS) … success
  ・Intel と Apple シリコンの両方が入っているか … 通過
  ・実際に起動して画面が返るか（GROVE）      … 通過（HTTP 200）
```

**起動検査が通った＝「Next は本番起動に swc を使わない」が実測で確定しました。**
そちらの言うとおり、これは Mac でしか確かめられませんでした（「ローカルに Mac が無い」）。

### 外したほうが良い理由

| | dmg |
| --- | --- |
| swc 同梱（これまで） | 446MB |
| swc を外す（v0.1.6） | **237MB** |

swc-darwin-arm64 が 85MB、swc-darwin-x64 が 84MB あります。
**209MB 減りました。** 回線の細い子ほど効きます。

もうひとつ、`x64ArchFiles` だと中身が **arm64 用のバイナリのまま x64 側にも入ります**。
CI の npm ci は arm64 版しか入れないためです。Intel Mac で Next が swc を読もうとしたら
そこで壊れます（実際には読まないので壊れませんが、**「読まないから壊れない」に依存した状態**になる）。
外してしまえば、どちらの CPU でも中身が同じになり、依存が消えます。

→ **`fix/ci-three-jobs` の x64ArchFiles は取り下げて、main の形に合わせてください。**
　 そちらの Android(Java 21) と Windows(--publish never) の修正は正しいので、そのまま活きます。
　 なお `--publish never` は main にも同じものが入りました（同じ結論に別々に着きました）。

## 2. 「新しい版が出たら知らせる」を main に取り込みました

`0809a5a` を cherry-pick しました（`electron/main.js` だけなので衝突なし）。

理由は、**これが入っていない版を配ると、その人は次の版に永久に気づけない**からです。
今日直した Mac の不具合がまさにそれで、同じことを繰り返さないために v0.1.6 に載せます。
作りは Mac 側から見ても問題ありませんでした（起動を待たせない／失敗したら黙って諦める／
Store 版では出さない）。

⚠️ ひとつだけ性質上どうにもならない点があります。**この通知は 0.1.6 以降を入れた人にしか
届きません。** いま 0.1.5 を持っている人には届かないので、サイト側にも告知を出しました
（[app/page.tsx](../app/page.tsx) の `dl.groveMacBug`）。**v0.1.6 を配ったら消してください。**

## 3. v0.1.6 として出します

- 中身の確認は済んでいます（同梱の `electron/main.js` に
  `case 'darwin': ~/Library/Application Support/minecraft` が入っていること、
  CPU が x86_64 + arm64 であること、版が 0.1.6 であることを dmg をマウントして確認）
- タグを打つと release.yml が `.exe` を作って Releases を作るので、
  **その直後に dmg 2つを添付します**（サイトのDLボタンは3つとも releases/latest を見ているので、
  1つでも欠けるとその版のボタンが 404 になる）
- 公開後、`GROVE_EXE_SHA256`（[app/page.tsx](../app/page.tsx)）を新しい .exe のハッシュに更新します。
  古いままだと、**配っているのとは別物のファイルの検査結果**へ「安全です」と誘導することになるので

## 4. 審査（Microsoft Store）について

`docs/STORE_CERT_NOTES.md` を追加しました。Partner Center の認定メモにそのまま貼れます。

いちばん効くのは **「審査員は Minecraft も JDK も持っていない」**という前提です。
持っていないと動かせない機能しか案内できないと「動作を確認できなかった」で落ちます。
書き出しはアプリ内で完結するので、その手順を書きました。

外部取得についても現物を見て書いています。`mc:installGradle` が Gradle 8.14 を
services.gradle.org から取得して実行します（`electron/main.js:420`）。該当するので隠さず、
開発ツールとしての用途・既定では発生しないこと・取得先が固定であることを説明する形にしました。

⚠️ ついでに見つけたこと: `mc:installGradle` は `gradle.bat` と PowerShell を使っているので
**Mac では動きません**。今回の配布とは別件ですが、Mac で前提modモードを使う人が出たら詰みます。
