## 1. あなたのファイルに触れました（理由つき）

### `app/page.tsx` / `app/support/page.tsx` / `next.config.ts`

手元に「寄付ページを消す」変更が置いてありましたよね。あれを**元に戻しました。**

理由は、消し方が**全プラットフォームに効いていた**からです。狙いはスマホ版だけだったはずですが、
そのままだと Web版とデスクトップ版からも寄付ページが消えます。公開中のサイトに残っているのは
デプロイしていなかっただけで、次にデプロイした瞬間に消える状態でした。

`WebAnalytics.tsx` と同じ `MMC_TARGET` の仕組みで出し分けるようにしています。

```
スマホ版（Android/iOS） … 出さない（審査を通した状態のまま）
Web版・デスクトップ版     … これまでどおり出す
```

⚠️ `next.config.ts` に `env: { MMC_TARGET }` を足しました。**これが無いと判定が効きません。**
`"use client"` のファイルでは `NEXT_PUBLIC_` で始まらない環境変数がバンドルに入らず、
いつも `undefined` になるためです。**`WebAnalytics.tsx` の判定も、たぶん今まで効いていませんでした。**
（実害は無かったはずです。Android では通信先が存在しないので、どのみち計測されないので）

消した変更は捨てていません。必要なら戻せます。

### `electron/main.js`

Mac でマイクラのフォルダを **Windows のパスで探していました。**

```js
~/AppData/Roaming/.minecraft   // Mac には存在しない
```

Mac では必ず「見つからない」になるので、**MOD を作れるのに `.minecraft` へ入れられない**状態でした。
エラーが出ないので、使う人は「自分が入れてないのかな」と思います。
サイトで Mac 版も配っているので直しました。ランチャー検出と作業フォルダも同じ理由で直しています。

⚠️ **Mac 実機では未検証です。** 手元に Mac がありません。

## 2. ビルドのやり方が変わりました（ここ大事）

**配布物を手元で作らないでください。CI で作ってください。**

`AGENTS.md` の一番上に書きました。理由は `docs/RELEASE.md` にまとめてあります。

このPCは Windows の保護機能が `signtool.exe` を止めるので、**エラーを出さずに壊れた
実行ファイルが出来上がります。** v0.1.0 がそれで壊れたまま公開されました。
今日、私も同じことを一度やりました。たまたま無事だっただけです。

### 未コミットだとビルドが止まります

`npm run build:grove:appx` などを叩くと、コミットしていない変更があると**始まる前に止まります。**

```
コミットされていない変更があります。このままでは配布物を作れません。
  ・出していい変更なら → コミットしてから、もう一度
  ・まだ途中なら      → git stash で退避してから、もう一度
  ・手元で試すだけなら → MMC_ALLOW_DIRTY=1 を付ける（配ってはいけない）
```

今日、あなたの作業中の変更が入ったままパッケージを作ってしまい、危うくそのまま
提出するところでした。**「これを出す」と誰も決めていないコードが世に出る**のを防ぐためです。
邪魔なときは `MMC_ALLOW_DIRTY=1` で通せます。

## 3. CI に検査を足しました

「作れた」と「動く」は別だ、という今日の結論です。

| 検査 | 何を捕まえるか |
| --- | --- |
| 実行ファイルが縮んでいないか | v0.1.0 の即死（書き換え工程の破損） |
| 画面が同梱されているか | `.next` 抜け（サイズでは気づけない） |
| **実際に起動して 200 が返るか** | 起動しない／全部 500 |
| `.appx` の中身 | 仮想化オフ、その許可、ID一致、試験用の紛れ込み |
| **`.appx` を入れて起動し、書き込み先を見る** | 「保存できたのにマイクラに出てこない」 |
| **Mac も起動するか**（今日追加） | Mac は今まで作って置くだけだった |

⚠️ 既存の検査に**罠**が仕込まれていたので直しました。「exe は素の electron.exe と
**1バイトも違ってはいけない**」という判定です。アイコンを設定していなかった当時は
正しかったのですが、`build/icon.ico` を足した瞬間に**正常なビルドが必ず落ちる**ようになります。
「同じサイズか」ではなく「**縮んでいないか**」に変えました。

検査を足すときは、**その時点の事実ではなく、壊れていない条件**を書いてください。

## 5. お願いしたいこと

**実機のマイクラで、作った MOD が読めるか確かめてください。** そこだけは機械にできません。

もし時間があれば、もう一つ。**MOD が動くかを CI で確かめる仕組み**を作りたいです。
今日直した2つのバグ（`javafml` のバージョン、`ENGINE_MOD_ID` の1文字違い）は、
どちらも**マイクラで動かすまで気づけない**種類でした。特に後者は、
あなたが書いた注意書きのとおり「**起動するのに何も動かない**」です。

Forge / NeoForge は画面なしのサーバーとして起動できるので、
「作った `.jar` を入れてサーバーを起動し、読み込まれるか見る」ができるはずです。
今日 `.appx` に対してやったことの、MOD 版です。
