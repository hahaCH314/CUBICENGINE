### エンジンを触らずに直せる範囲を、先に確かめる

`base-mod.jar` は javap で中身を読める。実際、監査4件は
**エンジンを1バイトも触らずに TS 側だけで直った**。

分かっていること（2026-08-23 実測）:

- `onTrigger` は**一致するルールを全部順に回す**（途中で抜けない）
- ルールごとに `conditions` を **AND** で見てから `actions` を回す
- `and` / `or` / `not` は実装済み。だから「ちがうなら」は
  条件を反転したルールとして出せる
- `DynamicRegistry` は `blocks` / `items` / `mobs` を読む（`mobs` は
  2026-08-23 夜にヒマワリが入れた。spec 2）
- モブは**エンティティを新しく作らない**。`base` のバニラモブを土台に、
  `<id>_spawn_egg` という**スポーンエッグのアイテム**を登録する形。
  だから作った子が描いた姿は出ない（村人かゾンビの姿になる）
- `addCreative` が登録したものをクリエイティブタブへまとめて入れる

「エンジン待ち」と書いてあっても、まず javap で見ること。
一度これで「ヒマワリ待ち」の1件が実は TS 側だけの話だと分かった。

## 4. このプロジェクトで一番高くつく失敗

**「動いているように見えて、実は何も起きていない」**

マイクラは失敗しても何も言わない。だから、

- **片方だけ直さない**
  `lib/javaEngine/spec.ts`（TS）と `public/base-mod.jar`（Java）は必ず同時に。
  一度これを怠り、全ユーザーが参加のたびに警告を見る `.jar` を出しかけた。
- **無言で消さない**
  変換できなかったカードは必ず画面に出す。`console.error` だけにしない。
  スマホには開発者ツールが無く、利用者は「押しても何も起きない」としか言えない。
- **推測で直さない**
  MIME と拡張子を2回続けて外し、何度もビルドをやり直させた。
  本当の原因は「端末にファイルマネージャーが無かった」だけだった。
