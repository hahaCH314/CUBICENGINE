## ⚠️ 1. リリースの前に `fix/ci-three-jobs` を入れてください

`chore(release): v0.1.6` を見ました。**その状態でリリースすると CI が3つとも落ちます。**
いま `fix/ci-three-jobs` で直して出しています。マージしてからにしてください。

### Android — 前からずっと落ちていた

```
[fatal] The Capacitor CLI requires NodeJS >=22.0.0
error: invalid source release: 21
```

Node 20 / JDK 17 の指定だった。Capacitor 8 は Node 22・Java 21 が要る。両方上げた。
**このジョブは以前から一度も通っていません。**

### Windows — 勝手に公開しようとしていた

```
⨯ GitHub Personal Access Token is not set
```

`package.json` の `build:*:win` / `build:*:mac` に `--publish never` が無く、
release.yml だけが CLI で渡していた。build.yml 経由だと publish 段階へ進んで落ちる。
スクリプト側に入れたので、どの叩き方でも公開しなくなった。

### Mac — `arch: universal` が実ビルドでエラーになりました

「実ビルドでの確認は未」と書かれていた件、**答えが出ました。エラーです。**

```
⨯ Detected file ".../@next/swc-darwin-arm64/next-swc.darwin-arm64.node"
  that's the same in both x64 and arm64 builds and not covered by the x64ArchFiles rule
```

`node_modules` は arm64 ランナーで一度だけ入るので、swc のネイティブは arm64 版しか
存在しない。x64 側と統合するときに electron-builder が判断できずに止まる。

`package.json` の `build.mac.x64ArchFiles` に `**/next-swc.darwin-*.node` を入れて、
そのまま含める指定にしました。

> ⚠️ **この修正が正しいかは、まだ分かりません。** こちらに Mac が無いので、
> 判定できるのは CI か、そちらの実機だけです。もし通らなければ、
> swc を同梱から外す（`!node_modules/@next/swc-*/**`）方向も考えられますが、
> 本番の Next が起動時に要求しないか確認が要ります。
> **起動検査があるので、外して落ちれば分かります。**

## 3. 「新しい版が出たら知らせる」を入れました

サイトから入れた人には更新を知る手段が無く、**大半が v0.1.4 のままです**
（GitHub の実測：v0.1.4 が 33 回、v0.1.5 は 1 回）。

起動3秒後に GitHub Releases の最新タグを見て、新しければダイアログで知らせる。
押すとダウンロードページを開くだけ。自動更新はしない。

- **macOS は署名が無いと自動更新できない**（Apple の仕様）。Developer Program が要る
- **Microsoft Store 版では出さない**（`process.windowsStore` で判定）。
  Store は自動更新するし、ストアアプリから外部DLページへ誘導するのは審査に触れる

⚠️ **この通知は 0.1.6 から効きます。** すでに配った版には入っていないので、
いまいる人には届きません。そちらがサイトに出した告知が、その人たちへの唯一の導線です。
