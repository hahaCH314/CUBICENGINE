## 2. 残っている1点：クリエイティブタブに出ない

`/give` では入手できるので、**ブロックの登録自体は正常です。**
持ち物の一覧に出てこないだけです。

`.class` を逆アセンブルして調べたところ、こうでした。

```
BlockItem の登録              : あり（DynamicRegistry.class）
CreativeModeTab への追加      : 見つからない
```

1.19.3 以降の Forge は、`BuildCreativeModeTabContentsEvent` で
明示的に追加しないとタブに並びません。そこが未実装のようです。

### 直し方（数行だと思います）

```java
@SubscribeEvent
public static void addCreative(BuildCreativeModeTabContentsEvent event) {
    if (event.getTabKey() == CreativeModeTabs.BUILDING_BLOCKS) {
        ITEMS.getEntries().forEach(item -> event.accept(item.get()));
    }
}
```

**私からは `.class` を書き換えられない**ので、エンジンの再ビルドをお願いできますか。
`public/base-mod.jar` を差し替えてもらえれば、こちら側は何も変えずに反映されます。

⚠️ もし再ビルドで modId が変わるなら、`lib/javaEngine/spec.ts` の
`ENGINE_MOD_ID` も同時に直してください。今は
`cubic_xxxxxxxxxxxxxxxxxxxxxxxx`（30文字）に合わせてあります。

## 3. こちらで直したもの（報告）

実機の前に、注入後の `.jar` を `javap` と展開で検証しました。
そのとき2つ見つけて直しています。

**① 日本語の表示名が捨てられていた**

`lang` に id を英語化した値（`Magicstone`）を入れており、
利用者が付けた「魔法の石」が消えていました。`displayName` を使うよう修正。

**② `ja_jp.json` が無かった**

`en_us` だけだと日本語設定のマイクラでは翻訳キーがそのまま出ます。
同じ内容を `ja_jp` にも出すようにしました。実機で日本語が出たのはこれのおかげです。

**③ 古いパスの残骸を削除**

`base-mod.jar` に `assets/cubicengine_generic/` が残っており、
assets 配下に別 modId のフォルダが2つある状態でした。実害はありませんが、
どちらが本物か追うときに迷うので消しています。

## 4. テクスチャについて（誤解を招かないように）

伊波さんが送ってくれたスクリーンショットで、ブロックが**紫と黒の市松模様**でした。

これは **私のテスト用 `.jar` の問題**で、エンジンの不具合ではありません。
Node 上で `canvas` を偽装して生成したため、81バイトのダミーPNGが入っていました。

本番の Web 経路では `createColoredTexture` が 16×16 の色付きPNGを作るので、
正しいテクスチャが入ります。**そちらは心配いりません。**
