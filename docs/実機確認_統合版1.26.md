# 統合版（Bedrock）1.26 の書き出し — 実機確認（2026-10-27）

> 何を見るか：**「プレイヤーが参加したとき → あげる（ダイヤ 64）」の作品を .mcaddon で書き出し、
> 統合版に入れて、ダイヤと起動メッセージが出るか。ブロックもゲームに出るか。**

## 確かめた環境

| もの | 版 |
|---|---|
| Minecraft for Windows（統合版） | 1.26.52（タイトル画面の表記は v26.52） |
| 書き出しの MC バージョン | 1.26.x（エディタの既定） |
| ワールド | サバイバル・チート ON・実験的機能なし |

ログは 設定 → クリエイター → 「コンテンツ ログ ファイルを有効化」をオンにすると、
`%APPDATA%\Minecraft Bedrock\logs\ContentLog*.txt` に出る（書き出しは少し遅れてまとめて出る）。

## これまでの結果

- **2026-10-27 ❌ ダイヤも起動メッセージも出ない**（ワールドを作ってすぐ）。
  スクリプト自体は読めている（`promoted [@minecraft/server] from [1.6.0] to [1.19.0]`、エラーなし）。
  参加の処理が `playerJoin` の 40 tick 後にプレイヤーを探していたが、その時点ではまだ体が出現していないことがある。
  調べた記録：
  - 12:33 の回：`playerJoin` → 40 tick 後は `players=`（空）→ そのあと `playerSpawn initial=true`。何も起きない
  - 12:34 の回：`playerSpawn` が先 → 40 tick 後は見つかる → ダイヤが届く

  ワールドを作った直後は出現まで時間がかかるので、毎回失敗する。
  → 「参加したとき」と起動確認を、`playerSpawn` の最初の出現（`initialSpawn`）で動かすように直した（`lib/codegen.ts`）。
- **2026-10-27 ❌ ブロックが出ない**：`blocks/custom_block.json | Block definition parsing failed`、
  続けて `The block named cubicengine:custom_block used in a "blocks.json" file does not exist in the registry`。
  `format_version: "1.20.10"` + `minecraft:unit_cube` は 1.26.52 では読めない。
  → `"minecraft:geometry": "minecraft:geometry.full_block"` + `format_version: "1.21.40"` にした（`app/editor/exporter.ts`）。
  MC バージョンに 1.20.x / 1.21.0 を選んだときは、ゲームより新しい版にならないよう、その版のまま書く（**こちらは実機で見ていない**）。
- **2026-10-27 ⚠️ 警告**：リソースパックの `blocks.json` に `format_version` が無いと、毎回警告が出る。バニラと同じ `[1, 1, 0]` を書くようにした。
- **2026-10-27 ✅ 直した版で動いた**。同じワールドに入り直すたびに「ダイヤモンド × 64 を受け取りました」と
  「[CUBICENGINE] アドオン起動！ イベント1個」が出た。ブロックのエラーと `blocks.json` の警告は消え、
  `/give @s cubicengine:custom_block` でテクスチャ付きのブロックが手に入った。
  まだ見ていないもの：新しく作ったワールドでの1回目、ブロックを置いたときの見た目、ほかのカード。
