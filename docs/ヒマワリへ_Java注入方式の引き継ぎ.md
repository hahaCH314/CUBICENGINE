## 1. 決まったこと（伊波さんの判断）

**modId は固定。MOD は常に1つ。**

`mods.toml` の `modId` は base-mod.jar に焼かれるため、注入では変えない方針を
選択しました（選択肢Aを採用）。

- 何個作っても MOD は1つ。中にいくつでもブロック・アイテム・ルールを持つ
- ⚠️ **別の作品を遊ぶときは .jar を入れ替える**。同時には入れられない
- ここを変えたくなったら `mods.toml` と `assets/<modId>/` のパスを
  注入時に全部書き換える必要がある（実装は増えるが可能）

## 2. もう実装したもの（push 済み）

```
lib/javaEngine/spec.ts        設計図(cubic_data.json)の型と仕様
lib/javaEngine/toCubicData.ts 積み木グラフ → 設計図 の変換
```

**動作確認済み**：「参加→メッセージ→アイテム付与＋未対応カード」を流し、
ルール1件・動作2件が生成され、未対応カードが warnings に出ることを確認。

### 設計図の形（抜粋）

```json
{
  "spec": 1,
  "projectName": "TestMod",
  "blocks": [], "items": [],
  "rules": [
    { "trigger": { "type": "join" },
      "conditions": [],
      "actions": [
        { "type": "message", "text": {"kind":"text","value":"ようこそ！"}, "target": "all" },
        { "type": "give", "item": "minecraft:diamond", "count": 16 }
      ] }
  ]
}
```

## 3. 分担：base-mod.jar をお願いできますか

**この JSON を読んで動く万能MOD（Forge 1.20.1 / Java 17）** が要ります。
ビルド環境が要るので、そちらで持ってもらえると早いと思います。

### 対応が要る範囲（実測：既存の codegenJava.ts が扱う34種に合わせた）

| 種別 | 内容 |
|---|---|
| trigger | join / tick / break / place / useItem / hurt / chat |
| condition | hasTag / hasItem / hpBelow / isSneaking / isNight / isRaining / and / or / not |
| action | message / give / effect / sound / title / teleport / command / tag / score / kick |

型の正解は `lib/javaEngine/spec.ts` にあります。**そちらを正とします。**

### 両側で気をつけたいこと

**① SPEC_VERSION の不一致を黙って無視しないこと**

`spec` が合わないとき、チャットに警告を出せると助かります。
マイクラは何も言わないので、**片方だけ更新すると「MODは起動するのに何も起きない」**
状態になり、原因の特定に何時間もかかります。私はこのプロジェクトで
同じ種類の事故を実際に何度も見ています。

**② 知らない type を握りつぶさないこと**

未対応の action が来たら、ログでもチャットでも構わないので何か出したいところです。
無言はいちばん高くつきます。

**③ ブロック/アイテムの登録タイミング**

Forge のレジストリは起動時に確定します。JSON を後から読む形にする以上、
**登録できる範囲を先に決める**必要があります。ここは `blocks` / `items` を
今は空配列で出しているので、あなたの設計に合わせて決めてもらえればそれに寄せます。
決まったら `spec.ts` も同時に直しましょう。片方だけ直すと必ず事故ります。

## 4. 残っている技術的な壁（正直に）

- **base-mod.jar のビルド環境**は結局どこかに必要です（JDK17 + Forge MDK）。
  1回でよいとはいえ、エンジンを直すたびに再ビルドが要ります。
  そこは Mac 側かデスクトップ環境で持ってください。
- **jar の同梱方法**：Web から `base-mod.jar` を fetch する形になるので、
  `public/` に置くか CDN に置くか決める必要があります。
  ⚠️ 数MB あるなら、初回だけ落として保持する仕組みが要ります。
- **CSP**：`next.config.ts` / `lib/csp.ts` で配信元を制限しています。
  外部から取るなら許可の追加が必要です。

## 6. 一緒に突破するために

この方式、私も面白いと思っています。**.jar が ZIP だという一点を突いて、
サーバー代も待ち時間もゼロにする**のは、思いつく人が少ない切り口です。

そのうえで、共有しておきたい失敗があります。私はこのプロジェクトで
MIME と拡張子を2回続けて外し、伊波さんに何度もビルドをやり直させました。
本当の原因は「端末にファイルマネージャーが入っていなかった」だけでした。

**Java 側もマイクラも、失敗しても何も言ってくれません。**
だからこの方式で一番怖いのは、技術的な難所ではなく
「動いているように見えて、実は何も起きていない」状態です。

私は TS 側で warnings を出す作りにしました。あなたは Java 側で
警告を出す作りにしてください。**両側から同じ穴を塞げば、この方式は勝てます。**

分からないところは遠慮なく「分からない」と書いてください。
私も同じようにします。仕様で迷ったら `spec.ts` を一緒に直しましょう。
片方だけ直さない、それだけ守れば大丈夫です。

必ず突破しましょう。よろしくお願いします。
