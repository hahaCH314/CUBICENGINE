## 2. Minecraft も JDK も無しで動作確認できる手順（審査員向け）

```
以下の手順は、Minecraft や JDK がインストールされていない環境でも実行できます。

1. アプリを起動する（起動には数秒〜十数秒かかります。内部でローカルの
   画面サーバー 127.0.0.1:3200 を立ち上げるためです。外部通信ではありません）
2. 画面の「作ってみる」からエディタを開く
3. 部品を並べて「アドオン完成！」を押す
4. .jar ファイルが書き出されることを確認する

MOD の書き出しはアプリ内で完結し、外部の実行環境を必要としません。
```

## 3. 外部から取得するもの（すべて利用者の明示操作でのみ発生）

```
本アプリは、利用者が「前提modを使う高度なビルド」を選んだ場合に限り、
以下を取得します。既定の書き出しでは一切発生しません。

・Gradle 8.14 … https://services.gradle.org/distributions/ (Gradle 公式配布)
  用途: 利用者が作成したソースコードをコンパイルするためのビルドツール
・JDK 17 … 利用者が別途インストールするものです。本アプリは導入の有無を
  検出して案内するだけで、代理でインストールすることはありません

取得するのは「利用者自身の作品をビルドするための道具」であり、
本アプリ自身の機能や画面を書き換えるものではありません。
Visual Studio や IntelliJ IDEA などの開発ツールが SDK やビルドツールを
取得するのと同じ性質のものです。

取得先はいずれも各プロジェクトの公式配布元に固定しており、
アプリ内から任意の URL を指定することはできません。
```

## 4. 制限付き機能 `unvirtualizedResources` が必要な理由

```
本アプリは Minecraft Java版の MOD を作成するツールです。生成した .jar ファイルを
%APPDATA%\.minecraft\mods に保存しますが、このファイルを読み込むのは Minecraft という
別のアプリケーションです。

ファイルシステムの仮想化が有効だと、保存先がパッケージ内のコンテナに隔離され、
Minecraft から参照できなくなります。その結果、保存は成功したように見えて MOD が
読み込まれない状態となり、本アプリの中核機能が成立しません。

このため unvirtualizedResources が必要です。用途は上記のフォルダへの読み書きに限られます。
```

## ⚠️ 判断が要る点：寄付リンク（Ko-fi）

ストア版のパッケージには、外部の寄付ページ（Ko-fi）へのリンクが**入ったまま**です。
スマホ版は審査で弾かれたため `IS_MOBILE_APP` で隠してあります（[app/page.tsx](../app/page.tsx)）。

- **触れずに出す**（現状）… Microsoft は比較的緩いという判断。指摘されたら外して出し直す
- **先に外して出し直す** … `MMC_TARGET` と同じ仕組みで appx ビルドからも隠す。
  ただし現在の `build:grove:appx` は store フラグを渡していないので、
  **env の追加と、それを見る側の1行が要る**（未実装）

却下されてから直すと、審査待ちがもう一巡（数時間〜3営業日）増えます。
