# NeoForge 26.1 の出し先 — 実機確認の手順（2026-10-18）

> 何を見るか：**「あげる」カード1枚の作品を 26.1 の NeoForge に入れて、実際に動くか。**
> 1.21.1 を開けたとき（2026-09-09）と同じ確かめ方。経緯は `lib/javaEngine/targets.ts` の
> `neoforge_1211` の行と、[監査_2026-09-07.md](監査_2026-09-07.md)。

## 用意するもの

| もの | 版 | どこから |
|---|---|---|
| Minecraft Java | 26.1.x | ランチャー |
| NeoForge | 26.1.2 以上 | neoforged.net（PrismLauncher ならインスタンス作成時に選べる） |
| Java | 25 | NeoForge のインストーラが要求する。21 では 26.1 が起動しない |
| GeckoLib | 5.5 以上（26.1 向け） | **前提modモード（geo モブ）を試すときだけ**。Modrinth / CurseForge |

## 手順（ふつうモード）

1. CUBICENGINE の設定で出し先を **NeoForge 26.1** にする。
2. 積み木で「プレイヤーが参加したとき → あげる（金のリンゴ 64）」だけの作品を作り、**完成済み .jar** で書き出す。
   ファイル名に `neoforge261` が入っていることを見る（1.21.1 用と取り違えない）。
3. PrismLauncher で NeoForge 26.1.2 のインスタンスを作り、`mods/` に .jar を入れて起動。
4. 見るところ：
   - 起動して MOD 一覧に CUBICENGINE が出る（出ないなら mods.toml か modId の問題）
   - ワールドに入った瞬間、金のリンゴ 64 個が持ち物に入る（＝読み込み・きっかけ・アクションが通った）
   - チャットに `[CUBICENGINE] 警告: SPEC_VERSION` が**出ない**こと
5. できれば追加で：ブロックを1つ置いた作品（クリエイティブタブ「建築ブロック」に出るか）、
   バニラ土台のモブ（スポーンエッグで湧いて名前と体力が当たるか）。
   1.21.1 でもここは未確認のまま（targets.ts の注記）。

## 手順（前提modモード・geo モブ）

26.1 では **GeckoLib 5** に変わり、モデルと動きの置き場所が `geckolib/models/` `geckolib/animations/` になった
（`targets.ts` の `geoDirs`）。ここが一番あやしいので、できれば見てほしい。

1. GeckoLib 5.5.x（NeoForge 26.1 向け）を `mods/` に入れる。
2. geo モブ1体の作品を前提modモードで書き出し、スポーンエッグで湧かせる。
3. 見るところ：**モブの形が出るか**。紫黒やエラーの四角で湧いたら、置き場所か識別子のズレ。
   ログに `Unable to find model` があれば置き場所、`animation.<id>.idle` 系の警告なら動きの名前。

## 結果の書き方

- 動いた → `lib/javaEngine/targets.ts` の `neoforge_261` に「✅ 日付・何が動いたか」を1行足す（1.21.1 の行と同じ形）。
- 動かなかった → 起動ログ（`logs/latest.log`）と、何をしたかをプロジェクトのスレッドに貼る。
  手元で直して配らないこと（AGENTS.md）。エンジンの直しは CI（engine-neo26.yml）で組み直す。

## まだ無いもの（知っておくこと）

- **ソース一式（MDK）の書き出しは 26.1 ではまだ出せない**（`lib/codegenJava.ts` が 1.21.1 の名前で生成するため、止めてある）。
- 26.2 / 26.3 は対象にしていない。NeoForge が 26.1 を「次の長く残る版」としているため。
